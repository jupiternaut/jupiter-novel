 1978 年,Dijkstra 写下 EWD 667,断言"用自然语言编程"是个糟糕的主意。
近半个世纪后,LLM 与 AI Coding Agent 已将"用人话写代码"变成了日常工程实践。
这位计算机科学的奠基者,究竟是被时代证伪,还是我们根本没有读懂他?01 · 回到 1978 年的那篇短文那一年,Dijkstra 在一篇仅两页的备忘录中,针对当时一种流行的设想开炮——既然编程如此困难,不如造一台能听懂人类母语的机器,人类便得以解放。Dijkstra 不认同这种思路。他的反驳可以归纳为三层:其一,界面的选择不是一道零和题。📌 这里的"界面"(interface)指两个系统之间传递信息的约定边界——机器码、汇编、高级语言、自然语言都是不同形态的人机界面,与我们今天常说的 GUI 不是一回事。
把工作甩给机器,并不意味着人类这一侧就能减负。跨界面的协作本身会产生额外成本,而一旦界面从"窄"变"宽",界面两侧的工作量往往同时上涨。这也是工程实践中偏好窄接口的根本原因。其二,数学史早已给出经验教训。
希腊数学受困于口述与图形化表达;阿拉伯代数曾尝试符号化,却又退回修辞式风格并最终式微;而现代科学的真正腾飞,依赖于 Vieta、Descartes、Leibniz、Boole 等人一步步将模糊的自然语言替换为精确的形式符号。其三,也是最具颠覆性的一点:形式符号不是负担,而是特权。我们使用母语时所感受到的那种"自然",其本质不过是——
它让我们很容易说出那些表面通顺、实则毫无意义的话。形式符号之所以让人觉得"难",恰恰是因为它拒绝让你说出这类话。02 · 那句带着冷笑的预言文章收尾处,Dijkstra 留下了一句颇具分量的直觉判断:能够用母语——无论是荷兰语、英语、法语还是斯瓦希里语——来编程的机器,制造起来恐怕和使用起来一样困难。站在 2026 年回望,这句预言对了一半,但更关键的另一半错了。• ✅ "制造起来困难"是准确的。 过去十余年,头部实验室为此投入的资金、算力与人才规模,足以让 1978 年的 Dijkstra 本人震惊。• ❌ "使用起来同样困难"这一点,他似乎低估了人类的适应能力。 我们确实把这类机器用起来了。那么,结论就是"Dijkstra 被证伪了"吗?答案并不这么简单。03 · 魔鬼藏在细节里:我们究竟是怎么"用"的?观察任何一个成熟的 LLM 工程实践,会发现一个颇具讽刺意味的现象:所有认真做事的团队,都在想方设法把自然语言"变回"某种形式化的东西。近几年 Prompt Engineering 与 Agent Harness 领域流行的几项实践:实践它实际在做的事用 XML 标签包裹输入(<context>...</context>)在自然语言中重建语法边界要求模型输出 JSON 而非自由文本在输出端重建形式结构Spec-driven development(先写规格再由 agent 实现)在指令端重建形式化契约Few-shot examples通过样本压缩指令的歧义空间Tool use / Function calling将关键动作从"描述"退回为"调用"Constitutional AI 与显式规则清单在价值层补上形式化约束规律是清晰的:我们并非真的在"用自然语言编程",而是在用一种"伪装成自然语言的、经过人工收窄的准形式语言"编程。Dijkstra 当年的判断是"自然语言是宽界面,两侧都要付出额外代价"——今天的 Prompt 工程师、Harness 设计者、模型训练者,正是这句话的活证据。04 · 真正被 Dijkstra 说中的部分重读 EWD 667,有三处放在 2026 年几乎具有预言级别的精度:预言一:"跨界面协作会产生额外工作量,界面越宽,两侧越忙。"对应今天完整的 Prompt Engineering 产业链。一份复杂任务的 Prompt 动辄数千 token,分段、示例、XML 一应俱全——这并非"用母语与机器对话",而是在设计一种临时性的、私有的形式化语言。预言二:"母语的自然,本质是容易说出听着正确、实则无意义的话。"对应今天的 LLM 幻觉问题。模型输出一段语法完美、逻辑自洽、连引用都精确到"某期刊某卷某期"的文字,而那本期刊根本不存在。这不是 Bug——这是自然语言的"自然"所固有的代价,被模型忠实地学会并放大了。预言三:"新文盲症会使相信自然语言编程的人更加盲目。"1978 年,这句话是 Dijkstra 对教育滑坡的批评。放到今天,它恰好指向另一群人:以为会打字就等于会写 Prompt、以为"把需求讲清楚"是一件容易事的人。 写过 PRD 的人都清楚:人类连用母语向另一个人类讲清楚一件事都做不到,又凭什么相信自己能够讲清楚给机器听?05 · 那么 Dijkstra 输了吗?我的判断是:他在战术上输了,在战略上赢了。• 战术层面,他认为没人能造出听懂人话的机器。事实上,我们造出来了。• 战略层面,他预言的"本质难题不会消失,只会换个地方出现"——这一点一字未错。过去,消除歧义这件事发生在编译器与程序员之间,由 Pascal、C、Haskell 的语法规则兜底。今天,消除歧义这件事发生在 Prompt 与 Harness 之间,由 Structured Output、Tool Schema、Eval Pipeline、Spec 文档兜底。难题的总量并未减少,只是完成了迁徙。它迁徙到了谁身上?迁徙到了那些正在设计 Agent Harness 的人、正在撰写 Cursor Rules 的人、正在调试 System Prompt 的人、正在为模型起草 Constitution 的人。这些人每天所做的事,本质上与 Dijkstra 当年做的事是同一件:在自然语言的泥潭中,一点点、审慎地收窄那个界面。06 · 三条留给今天的启示其一,不要将 LLM 的"能听懂人话"视作免费午餐。
每一次"它理解了",背后都有人在某处支付了让它理解的成本——训练数据、RLHF、System Prompt、Tool Schema、Eval、Harness。其二,写好 Prompt 的核心能力不是文采,而是形式化思维。
能够把一件事讲清楚的人,写 Prompt 才具有优势。而"把一件事讲清楚"这项能力,从来都是形式化训练的产物,与母语熟练度无关。其三,真正稀缺的能力,是在自然语言与形式符号之间自由切换。
单纯的形式化思维(传统程序员)与单纯的自然语言表达(非技术使用者)都已不敷使用。新的稀缺能力是:清楚什么时候应当借助自然语言的表达力,什么时候应当退回到形式符号的精确性。参考:E.W. Dijkstra, "On the foolishness of 'natural language programming'", EWD 667, 1978.

## 答 1

不是巴别塔——这个隐喻反而会误导你。

巴别塔的核心是**分裂的诅咒**:本来一体的语言被打散,各支彼此平行、互不通约。但自然语言和形式语言根本不在同一个坐标系上,它们不是"两种语言",而是**同一件事的两种相态**。

更贴切的几个框架:

**波函数与坍缩**。自然语言是叠加态,同一句话在不同读者头脑中坍缩成不同含义;形式语言是被强制坍缩的本征态——它的语法机制让你**没办法**说出"听着对、其实没坍缩"的话。LLM 在做的事很微妙:它没有真正坍缩自然语言,而是对叠加态做加权采样。所以幻觉永远存在,那是采样的方差,不是 bug。

**热力学梯度**。语义的不确定性是一种熵。把自然语言转成形式语言不是翻译,是降熵——降熵必须支付能量(Schema、Eval、Tool 定义、Spec 文档)。Prompt Engineer 本质上在做麦克斯韦妖的工作:逐 token 地把信息从混沌一侧拨到有序一侧。

**静态语义 vs 动态语义**。形式语言是 static,意义在定义时锚定;自然语言是 dynamic,意义在读取时由上下文求值。LLM 试图通过海量语料把 dynamic 近似成 static,但 dynamic 有不可消去的部分——所以"近"永远只是"近"。

Dijkstra 那篇真正的杀招藏在那句"母语的自然,本质是容易说出听着正确实则无意义的话"。他在说一件更狠的事:**我们对自然语言的舒适感,不是对表达力的舒适,而是对不必承诺的舒适。**形式语言让人觉得难,不是语法陌生,是它**剥夺了模糊承诺的权利**。

所以如果非要保留巴别塔的意象,我会反着写——人类不是失去了通用语言,**人类从来就没有过通用语言**。形式化不是想重建巴别塔,形式化是承认巴别塔从未存在,所以宁愿在每个微小局部、用人工挖出的小水渠,把意义一段一段引导到精确处。每个 XML 标签、每个 Tool Schema、每个 Constitution 条款,都是一节小水渠。

Dijkstra 半个世纪前就把账算清了:**消除歧义的工作量是守恒的。你只能选择把它交付给谁。**

上一回合我用了波函数/热力学/巴别塔的隐喻——那是诠释,不是剖析。这一轮按 /decision 把这篇 EWD 667 拆到最里面,看 Dijkstra 究竟说了什么。

### ━━━ STAGE 1 ━━━

#### Round 1:Dijkstra 那篇短文,到底在论证什么?

🔴 **红方(单一工程预测说)**

Dijkstra 在做一个关于工程可行性的预测。原文最后那句"造起来困难、用起来同样困难"是论点核心——他认为自然语言编程在技术上做不出来,因为机器没办法消化自然语言固有的歧义。所以这是一个**关于机器的判断**。
- **承重假设**:Dijkstra 论证的核心建立在"自然语言的歧义无法被算法消除"这一技术判断上。

🔵 **蓝方(认知论判断说)**

不对。Dijkstra 真正在论证的不是机器,是人。他原文里最锋利的一刀不是"造不出来",而是那句"母语的自然,本质是它让我们很容易说出听着通顺、其实毫无意义的话"。这句话不依赖机器存不存在——它是一个关于**自然语言这个媒介的本性**的判断。即便机器能完美听懂自然语言,使用者依然会困在"以为自己说清楚了,其实没有"的陷阱里。所以原文的论点是**关于人和语言的关系**。
- **失败触发**:如果把这篇当工程预测读,那 LLM 的出现就直接证伪了它,这篇文章就只剩历史价值——但实际上 2026 年读它依然刺骨,这说明"工程预测说"漏掉了原文真正的力量来源。

🪞 **Reflection 1**

红蓝双方都假设 Dijkstra 在做**单一论断**,只是争论这个论断的层次。但回到原文,Dijkstra 实际上同时做了三层论断,只是他没明示分层:

1. **工程层**:听懂母语的机器造起来很难(经验预测)
2. **认知层**:跨越宽界面的工作量两侧都要支付,母语的"易"是一种伪装(信息论判断)
3. **教育层**:相信"会说人话就能编程"的人会变得更盲目(社会判断)

红蓝双方都把这三层混在一起,结果产生了一场伪辩论——"Dijkstra 错了 vs 没错"取决于你看哪一层。

▶ **第 2 轮输入**:Dijkstra 的三层论断,在 2026 年各自的强度是多少?

#### Round 2:三层论断,哪一层经得起 LLM 时代的检验?

🔴 **红方(认知层最深说)**

三层论断里,工程层确实部分被证伪——LLM 造出来了。但**认知层那一层**,核心是关于宽界面/窄界面的工作量分布,这个论断不依赖于机器能否听懂自然语言。它说的是一件信息论意义上的事:**消除歧义的总工作量不可压缩**。LLM 没有消除歧义,只是把消除歧义的工作从"程序员写代码"转移到了"prompt engineer + harness 设计 + RLHF + spec 文档 + tool schema"。整个 prompt engineering 产业链就是 Dijkstra 这一论断的活证据。教育层那一层(新文盲症)同样命中——以为"会打字就会写 prompt"的人,正是 Dijkstra 当年描述的那群人。
- **承重假设**:消除歧义的工作量,在不同主体之间总和守恒。

🔵 **蓝方(守恒律不成立说)**

"工作量守恒"听起来漂亮,但其实是一个未经证明的猜想。LLM 真正做的事可能违反了这个守恒律。它把消除歧义的成本**外摊**到了不在场的第三方——人类几十年来在互联网上写下的几千亿 token,提供了"何为正常表达"的隐含约定。这些约定被 internalize 进权重,使得每个具体使用者面对的边际成本急剧下降。从单个 prompt engineer 的视角,他付出的工作量远远小于"半个世纪前一个程序员把同样规格的逻辑用 Pascal 写出来"所需要的工作量。
- **失败触发**:如果"工作量守恒"是真的,那 LLM 应该没有真正的生产力提升——只是把同样的活换了个人干。但实际经验显示生产力是上升的。要么守恒律不严格成立,要么 Dijkstra 的论断需要修正。

🪞 **Reflection 2**

关键变量浮现了:**歧义消除的工作量,能否被分摊到不在场的第三方?**

| | 红方立场 | 蓝方立场 |
|---|---|---|
| 守恒律是否严格 | 严格 | 不严格,可外摊 |
| 验证方式 | 看 prompt eng 整体投入 | 看单个使用者的边际成本 |
| 争议类型 | 经验/定义之争 | |

但争论双方都没看到一条**第三路径**——

Dijkstra 真正的洞察可能不是"工作量守恒",而是更精细的一句话:**模糊性责任不可消解,只能内化或转移**。LLM 没有消除模糊性,它把模糊性**内化进了系统本身**。所以使用者每一次和 LLM 交互,本质上都是在和"一个内化了人类全部模糊性的系统"打交道。幻觉、错位、偏离意图,这些不是 bug 而是必然——它们是被吞进系统内部的那些模糊性,在 inference 时漏出来的样子。

▶ **第 3 轮输入**:既然模糊性责任不可消解只能转移,我们今天该用什么姿态对待 Dijkstra 这篇文章?

#### Round 3:对 2026 年的实践者,这篇文章应该是什么角色?

🔴 **红方(诊断工具说)**

Dijkstra 这篇应该被当作一个**长期有效的诊断工具**。每当看到"AI 让一切都变简单"的叙事——AI 写代码、AI 写文档、AI 做决策——都要问一句:**"那么消除歧义的工作现在由谁来支付?"** 这一问能立刻拆穿大量营销噪音。它能帮你识别:哪些 AI 应用是真的让事情变容易了(因为模糊性恰好被恰当内化了),哪些只是把模糊性藏到了下游(直到生产事故的时候才暴露出来,然后由运维或客户支付)。从这个意义上,EWD 667 是 1978 年写给 2026 年的备忘录。

🔵 **蓝方(警惕过度引用说)**

但把 Dijkstra 抬得太高也有风险。LLM 时代真正新的东西——emergent capabilities、in-context learning、tool use、agentic loops——这些是 1978 年根本不存在的概念。如果你只用"自然语言 vs 形式语言"的二元镜头去看 LLM,你会错过这些新物种的本质。Dijkstra 的框架在它能命中的地方很锋利(诊断营销叙事、识别工作量转移),但它没有词汇去描述"模型在 inference 时通过 attention 机制实时合成上下文相关的小型形式语言"这件事。把 EWD 667 当圣经,可能会让人在面对真正的新东西时反而看不见。

🪞 **Reflection 3**

红蓝的争论本质上是一个 **value judgment**:你把 LLM 视为"老问题的新形态"还是"真正的新物种"?

数据无法解决这个问题——这是一个**认知保守度**的选择。

- 如果你倾向"老问题新形态" → Dijkstra 是诊断工具,用它来抵抗营销噪音
- 如果你倾向"真正的新物种" → Dijkstra 是历史文献,继续用 1978 年的框架会错过现在真正在发生的事

可分类清楚了:
- **数据可解的争议**:工作量守恒是否严格成立(原则上可经验测量,但缺数据)
- **价值判断的争议**:LLM 是连续演化还是范式跃迁(必须使用者自己决定)

#### 关键变量 1:工作量是否守恒

**子命题分解**:

- **A**: 自然语言到机器执行需要消除歧义 → 🟢 信息论意义上的硬事实
- **B**: LLM 的 inference 调用,边际工作量远小于传统编程 → 🟢 经验上明显成立
- **C**: 整个 LLM 训练 + RLHF + harness 的总工作量,是否大于等于历史上"用 Pascal 写同样规格代码"所需的总工作量 → 🔴 没人做过这个核算

**敏感度 / 可观测性 / 可控性**:

| 属性 | 评估 |
|---|---|
| 敏感度 | 高 — 决定了 Dijkstra 守恒律的严格程度 |
| 可观测性 | 低 — 几乎没人会真去算 LLM 训练的全人类时间投入 |
| 可控性 | 不可控 — 这是事后核算问题 |

**结论**:无法定论。但**即便严格守恒律不成立,弱化版"工作量在主体间转移"是显然成立的**——这就是 Dijkstra 思想最稳的内核。

#### 关键变量 2:模糊性内化机制

**子命题**:LLM 没有消除自然语言的模糊性,而是把它内化进权重 → 🟡 这是一个机制性判断,有理论支持(LLM 是统计模型),但严格证明需要 interpretability 研究的进展。

**为什么这条比"工作量守恒"更深**:它解释了为什么幻觉、为什么 prompt 设计这么微妙、为什么"形式化收窄界面"(XML 标签、JSON schema、tool spec)在工程实践中反复出现——因为只有形式化才能强制把模糊性挤出系统。

### ━━━ FINAL VERDICT ━━━

#### 用通俗的话讲,Dijkstra 原文到底说了什么

**一句话版本**:
> "用人话跟机器交流听起来轻松,其实只是把消除模糊的工作藏到了别处——藏到机器制造的难度里、藏到使用者的盲目里、藏到训练数据里——但它不会真的消失。"

**三句话版本**:

1. 自然语言是个"宽"界面,什么都能塞进去,听起来好用——但任何要去执行它的系统(机器或人脑),都得先把它"窄"下来,这个窄化的工作必须有人做。
2. 形式语言之所以让人觉得难,不是因为它真的难,而是因为它**不允许你说出听着对、其实没意义的话**。这种"不允许"是它的优点,不是缺点。
3. 所以"用自然语言编程"不是技术问题,是一个**责任转移问题**——你不写形式化代码,那么形式化的工作就被推给别人:编译器作者、prompt engineer、harness 设计者、RLHF 标注员、或者最终是替你善后的运维。

#### 翟志军文章的贡献,用通俗话讲

他把 Dijkstra 的预言对账了一遍,得到一个干净的结论:

> Dijkstra 战术上输了——机器真的造出来了,人也真的用上了。
> Dijkstra 战略上赢了——他预言的"难题不会消失,只会换地方出现",一字未错,只是搬到了 prompt engineer 的办公桌上。

#### 我的判断(不是 Dijkstra 的,也不是翟志军的)

EWD 667 真正的内核不是"自然语言 vs 形式语言"这个二元对立,而是一个更精细的洞察:

> **模糊性责任不可消解,只能内化或转移。**

LLM 时代的所有奇怪现象——幻觉、prompt 敏感性、agent harness 越搞越复杂、spec-driven development 流行、tool schema 成为标配——都是这条规律的不同侧面。你看到 prompt 越写越像伪代码,这不是巧合,是模糊性在被一点点挤出系统的过程。

#### 你以后该怎么用这篇文章

把它当一面镜子,照在每一句"AI 让 X 变简单"的话上。然后问:

> **"那么,消除歧义的工作,现在由谁在支付?"**

如果答得出来,这个 X 是真的变简单了(成本被合理内化或可控转移)。
如果答不出来,这个 X 没变简单,只是你看不见的人在替你支付——通常是几个月后的你自己,在调试一个生产事故的时候。

- 🟢 高确定性:跨界面工作量两侧都要支付(信息论级硬事实)
- 🟢 高确定性:形式化的"难"本质是它拒绝模糊承诺(原文核心)
- 🟡 中确定性:LLM 通过权重内化了人类语言的模糊性(机制判断,缺 interpretability 证据)

## 答 3

这两句是 EWD 667 的两个不同支柱,前者是**力学事实**,后者是**心理事实**。两个加在一起才能解释为什么自然语言编程是个伪命题。

### 第一句:跨界面工作量两侧都要支付

**先解释"界面"**

界面就是两个系统之间约定的传递信息的边界。你和银行 ATM 之间的界面是按键和屏幕。你和编译器之间的界面是源代码语法。你和 LLM 之间的界面是 prompt。

**界面有"宽窄"之分**

- **窄界面**:能塞进去的东西种类有限,格式严格。比如 Python 语法——你只能写出符合规则的字符序列,其他都报错。
- **宽界面**:能塞进去的东西几乎无限,格式宽松。比如自然语言——你想怎么说怎么说。

**核心断言**

界面的"宽度"不是免费选择。一个界面有多宽,**通过它的信息就有多模糊**。模糊的信息要变成可执行的动作,必须在某个地方被消解掉。**这个消解工作不会因为你换了个界面就消失**。

**举个生活例子**

你去面馆点单,有两种点法:

- **窄界面**:递一张表格,上面写死了"汤底=牛骨,面条=细面,辣度=2,加蛋=1"。老板照做。
- **宽界面**:你说"老板来碗好吃的,辣一点别太辣,我今天有点累"。

第二种你说得轻松,但**老板这边的工作量爆炸了**——他得猜"好吃"是什么、"辣一点别太辣"在你的口味坐标系里是几度、"今天有点累"暗示要清淡还是要补。他要么猜对(消耗他的脑力),要么猜错(消耗你下次再来的耐心),要么反复问你(把工作推回给你)。

**界面变宽的那一瞬间,工作量没有减少,只是换了个支付者**。Dijkstra 把这件事抬到信息论高度:这不是工程师不努力,是数学结构决定的。模糊的输入变成确定的输出,这中间的"信息差"必须有人填,只是填在哪一侧的问题。

**对应到 LLM**

你写"帮我做个登录页"——比写 React 代码轻松多了。但这个轻松不是凭空来的:
- 一部分由模型在训练时学过的几百万个登录页吸收了
- 一部分由你下一句"不是这种,要更简洁"补回去
- 一部分由 system prompt 工程师预先设计好的约定吸收了
- 一部分,在线上事故发生时由你自己付清

总账,**没少**。

### 第二句:形式化的"难",本质是它拒绝模糊承诺

这一句是 Dijkstra 整篇文章里最锋利的洞察,但它的方向跟人们的直觉相反。

**人们通常以为**

- 形式语言难,是因为符号陌生、规则严格、要记的东西多。
- 自然语言易,是因为我们从小就会。

**Dijkstra 说**:这是错觉。形式语言的"难"和自然语言的"易"是同一件事的两面——

> **形式语言之所以让你觉得难,是因为它不允许你说出"听起来对、其实没意义"的话。**
> **自然语言之所以让你觉得易,是因为它允许。**

**举个例子**

你在饭桌上说:"我觉得人生的意义在于追求真实的自我。"

旁边人点头。这句话听起来很对。但你试试用形式语言重写:

- "真实的自我" → 给我一个定义,定义里不许循环引用
- "追求" → 给我一个具体的可观测动作
- "意义" → 你是说效用函数,还是说目的论,还是说体验主观价值?

写到第二步你就写不下去了。**不是因为形式语言难,是因为你那句话原本就没有清楚的意思**——只是听起来像有。

自然语言允许你**承担"听起来有意义"的社交收益,而不必支付"真的把意思说清楚"的认知成本**。这是它最大的便利,也是它最深的陷阱。

**为什么这一点对编程致命**

代码必须执行。执行不接受"听起来对"——CPU 没法运行一段含义模糊的指令。所以**编程必然是一个把模糊承诺挤出去的过程**。

形式语言把这个挤出过程**挪到了你写代码的时候**——当你写不出来的时候,你就被迫意识到"我其实没想清楚"。

自然语言编程把这个挤出过程**挪到了运行的时候**——你写得很顺,看起来都对,运行时炸了,因为模糊的部分一直在,只是被推迟到执行阶段才暴露。

**对应到现在**

你写 prompt 的时候那种"很顺、看起来都对"的感觉——那不是你写得好,那是自然语言固有的"易"。然后模型的输出有时候很惊艳、有时候完全离题,那不是模型不稳定,**那是你那个"很顺"的 prompt 里本来就有没消解的模糊,模型只是替你把模糊变成了某种确定的输出**(可能是你想要的,也可能不是)。

为什么资深的 prompt engineer 会本能地用 XML 标签、JSON schema、few-shot examples——不是因为这些"显得专业",**是因为这些是把"模糊承诺"从 prompt 里挤出去的工具**。他们在用形式化结构,强迫自己说清楚自己到底想要什么。这恰恰是 Dijkstra 推崇形式化的全部理由。

### 两句话合起来

第一句告诉你:**自然语言不会让事情变简单,只会让简单换个地方藏起来。**

第二句告诉你:**那个"藏起来"的具体机制,是允许你说出听起来对、其实没意义的话——这种允许在社交场景下是个特性,在编程场景下是个 bug。**

加起来就是:用自然语言写代码,等于让你拿着一个允许模糊承诺的工具去做一件不容许任何模糊的事——结果就是模糊不会消失,只会迁移到别人(或未来的你)那里去爆。

## 问 4

你的解读过去偏向真理了，我需要知道对于现实生活和写prompt以及vibe coding有什么指导

## 答 4

公允批评。前面把 Dijkstra 抬到了"信息论级硬事实",这种语言离地三尺,落不下来。下面把它砸到地上。

### 一条主轴线

把那两句话翻译成一个可以贴在桌上的判断准则:

> **每次你觉得"这事儿说得很顺",立刻停下来问一句:"我是真的说清楚了,还是只是说出了一句听起来对的话?"**

这一句是这篇文章对你日常的全部价值。下面的所有指导都是从这一句长出来的。

### 写 prompt 的具体指导

#### 1. "顺"是危险信号,不是好信号

prompt 写得很顺、不需要修改、看起来挺完整——这种感觉**本身就是 Dijkstra 警告的那个陷阱**。自然语言给了你这种顺畅感,作为代价它没有强制你想清楚。

**操作准则**:写完一个 prompt,在发出去之前,逼自己回答三个问题——

- 如果模型完全按字面意思执行,会发生什么?(往往会发现你写的不是你想的)
- 我有没有用到任何含糊的限定词?("简洁"、"专业"、"合适"、"流畅"——这些都是模糊承诺)
- 这个 prompt 如果给两个不同的人,他们交付的东西会一样吗?(差距越大,你写得越糊)

#### 2. 用结构强制你自己想清楚

XML 标签、JSON schema、分段标记——**这些工具的真正用户不是模型,是你**。

模型其实在没有结构的纯散文 prompt 下也能工作。但**当你被迫填一个 schema 的时候,你会被迫面对"我到底想要什么"这件事**。这就是形式化的全部价值——它不允许你滑过去。

**操作准则**:对任何重要的 prompt,先用一个粗结构画骨架——

<目标>...</目标>
<输入>...</输入>
<约束>...</约束>
<输出格式>...</输出格式>
<不要做的事>...</不要做的事>

不是给模型看的,是给你自己看的。每一段你填不下去的地方,就是你没想清楚的地方。

#### 3. "不要做什么"比"要做什么"信息量大十倍

自然语言天然倾向于正面描述("写得专业一点"),正面描述天生模糊。负面描述("不要用项目符号"、"不要重复用户的问题"、"不要加免责声明")**反而是窄的**——因为它直接砍掉一片可能性空间。

**操作准则**:每个 prompt 里至少有一条明确的禁止项。如果你想不出禁止什么,说明你对自己想要的东西还不够清楚。

#### 4. 把模糊推到 example 里,而不是形容词里

你说"写得简洁",这是模糊承诺。你贴一段你认为"简洁"的样例,这是窄界面。

**操作准则**:形容词 → 样例。每一次你想用形容词的时候,问自己能不能换成一个具体的例子。

#### 5. 一次失败不要靠"再说一遍"修复

模型输出离题,人的本能是在 prompt 后面加一句"不是这样的,我要的是 X"。这是把模糊推给模型自己消解,**短期能过,长期会让你的 prompt 越来越长越来越糊**。

**操作准则**:输出离题时,回到上游,定位**原 prompt 里哪句话允许了这种解读**,删掉或改写。问根源,不要打补丁。

### vibe coding 的具体指导

vibe coding 是 Dijkstra 警告最对口的现代场景——你用人话描述需求,模型生成代码,你不读代码就能跑。这个流程的"轻松"完全建立在"模糊性藏在某处"的前提上。

#### 1. 知道模糊性藏哪儿了

vibe coding 项目里的模糊性,几乎总是藏在三个地方:

- **错误处理**(模型默认会假设 happy path)
- **边界条件**(空输入、超大输入、并发、网络失败)
- **数据契约**(字段名、类型、null 还是 undefined、时区)

**操作准则**:写 vibe coding 的 spec 时,这三块必须明示。不是为了模型,是为了让**你自己**意识到这些地方有决策要做。模型不替你做决策——它只替你**假装**做了决策。

#### 2. 区分"能跑"和"对"

模型生成的代码运行起来不报错——这只意味着语法层面的歧义被消解了。**业务逻辑层面的歧义还在**,只是被某个具体的实现选择"暂时压住了"。这种压住是任意的,经不起需求迭代。

**操作准则**:对任何 vibe coded 的代码,在你"觉得它对"和"知道它对"之间画一条线。后者需要你**用形式化的方式重读一遍**——读测试、读类型签名、读边界 case 处理。这一步不可省。省了的话,你只是把问题推迟到生产事故那一天。

#### 3. 给 spec 写测试,不是给代码写测试

传统流程:写代码 → 写测试 → 跑通。
vibe coding 流程应该反过来:**写 spec → 把 spec 翻译成测试用例 → 让模型生成代码 → 测试用例通过即视为"模糊已被消解"**。

测试用例就是你的窄界面。**它不允许"听起来对"——要么过,要么不过**。

**操作准则**:vibe coding 之前,先写出 5-10 个具体的输入输出对(不是测试代码,就是表格)。这 5-10 个对子是你的"形式化锚点"。模型生成的代码必须满足它们。

#### 4. 警惕"模型已经懂了"的错觉

模型没懂任何东西。它在做模式匹配。当它"懂了"的时候,意味着它把你那段模糊的 prompt **匹配到了训练数据里某个最相近的模式上**。这个模式可能恰好是你想要的,也可能只是统计意义上最像。

**操作准则**:每次模型表现得"出乎意料地懂",反而要警惕——它可能正在调用一个跟你需求**形似但神不似**的模板。让它解释一下它是怎么理解你的需求的,看看跟你的实际意图差多少。

#### 5. vibe coding 的真实成本曲线

它的曲线长这样:

- **起步阶段**:成本极低,产出很快,看起来魔法
- **第一次维护**:成本陡增,因为你不熟悉自己的代码
- **需求变更**:成本进一步增,因为之前压住的模糊性在新需求下崩开
- **生产事故**:成本爆炸,因为错误处理和边界条件的模糊一直没被消解

**操作准则**:对你**自己用一次就扔的脚本**,vibe coding 是大杀器,放心用。对**会被维护的代码**,vibe coding 必须配合形式化补救——写测试、写类型、做 code review,把模糊性挤出去。否则你不是在写代码,你是在攒债。

### 现实生活的指导(超越 prompt)

这一节是 bonus,但其实是 Dijkstra 思想最大的回报。

#### 1. 听到"听起来很对"的话,启动警报

会议上有人说"我们要打造卓越的客户体验"——这是模糊承诺的典型形态,听起来无可反驳。问一句:"具体指什么 metric 上升?"

家里有人说"你最近不够关心我"——同样的结构。问一句:"哪件具体的事情让你这么觉得?"

**这不是抬杠,这是把模糊性挤出去的合作动作**。承担挤出工作的人,才是真的在沟通。否则双方都在自然语言的"易"里互相点头,但什么都没说清楚,埋下下一次冲突的种子。

#### 2. 你给自己写的 todo,默认是 prompt

"看一下那个项目"——典型的模糊承诺。你今天写下、明天看到、永远不会做。

把它改成:"周三晚上 8 点,打开 X 仓库的 README,读 30 分钟,记下三个问题。"

这是形式化的 todo。它不允许你滑过去。

#### 3. 决策时辨别"分析"和"听起来很有道理的话"

很多人(包括 LLM)给你的"分析",其实是把若干听起来有道理的句子按合理顺序排列。**把每一句话单独拎出来问"这一句的承重是什么?证据是什么?"——一半的句子会塌掉**。

塌掉的那些不是分析,是叙事的填充物。

### 最后一句

这篇文章给你的不是一个新工具,**是一个新的怀疑姿态**:

> 看到任何"轻松"、"自然"、"流畅"、"听起来挺对"的东西,先别接受。
> 先问一句:**这个轻松是真的轻松,还是某个看不见的人正在替我支付?**
>
> 如果答得出"是某某地方真的吸收了这个成本",那就是真的轻松,放心用。
> 如果答不出,那就**还没消解的模糊性正在等你**——可能等几小时,可能等几个月,但它一定会出现。

这个怀疑姿态,就是 Dijkstra 写 EWD 667 想留给后人的全部东西。

### 这篇文章是谁写的、为啥重要

1978 年,一个叫 Dijkstra 的荷兰计算机科学家,写了一篇两页的小文章。

他在计算机界的地位,大概相当于物理界的爱因斯坦——属于"开山祖师"那一档的人。所以他随手写的两页东西,半个世纪后还有人在读。

那一年发生了什么?当时有一种很流行的想法,大概是这样:

> "编程太难了,要学一堆奇怪的符号和规则。要是有一天,我们能直接对着电脑说人话——'帮我做个表格'、'帮我算个工资'——电脑就能听懂、就能做出来,那该多好啊。"

这个想法听起来特别美好,对吧?Dijkstra 看到之后,坐下来写了篇文章,标题翻译过来就是——

**《"用人话编程"是个蠢主意》**

(他是真用了 foolishness 这个词,不是我夸张。这老头说话就是这么冲。)

### 他到底说了啥

我用一个完全不涉及计算机的故事来讲他的核心意思。

#### 故事:餐馆点菜

想象两家面馆。

**A 面馆**:老板娘是个 60 岁的山西大妈,跟你认识 20 年。你一进门坐下,她瞥你一眼说"今天看你脸色不好,我给你下碗清淡的"。你点点头,五分钟后端来一碗刚刚好的面。

**B 面馆**:连锁快餐,你得在屏幕上点。汤底——选一个;面条——选一个;辣度——0/1/2/3;加蛋——是/否。点完付钱,机器出餐。

A 面馆,你说话超轻松,几乎不用动脑。
B 面馆,你得做一堆选择,有点烦。

**问题来了:为什么 A 面馆这么轻松?**

很多人会说:因为大妈聪明、有经验、懂你。

但 Dijkstra 的眼睛会看得更深一层——他会说:

> **A 面馆的轻松不是凭空来的。是大妈在替你做那些选择。**
>
> 你说"清淡",在她的脑子里,这句话被翻译成了几十个具体决定:用什么汤底、放不放姜、面条粗细、辣不辣、要不要加香菜。
>
> 这些选择没消失。只是从你这边,挪到了她那边。

这就是 Dijkstra 整篇文章的第一个核心观点:

> **当你说话越轻松,就一定有人在替你做更多的工作。这件工作不会消失,只会换个人做。**

#### 那"用人话编程"为啥是蠢主意?

继续这个故事。假设有人发明了一台"听得懂人话的电脑"。你说"帮我做个工资表",它就给你做出来。

听起来跟 A 面馆一样美好,对吧?

Dijkstra 说:你别高兴太早。问题在于——

**电脑不是认识你 20 年的山西大妈。**

你说"做个工资表",这背后藏着一堆电脑没法猜的问题:

- 哪些人的工资?
- 算税前还是税后?
- 加班费怎么算?
- 请假扣多少?
- 试用期的人按什么标准?
- 表格用什么格式?Excel 还是 PDF?
- 给谁看?老板?员工本人?会计?

这些问题,**总得有人回答**。

只有两种可能:
1. 你来回答(那你说"做个工资表"就没意义了,你最后还是得说清楚)
2. 电脑替你"猜"(那它必然经常猜错,因为它不认识你)

**没有第三种可能**。这就是 Dijkstra 的核心洞察——你以为"会听人话的电脑"能让事情变简单,但实际上,**那些复杂的事不会消失,只会换个地方藏起来**。

### 他还说了一件更狠的事

上面那个还只是开胃菜。Dijkstra 真正最锋利的一刀,是下面这个。

他说:**人话有个特别危险的特点——它允许你说出"听起来很对、其实没意义"的话。**

举几个例子你就懂了:

- "我们要打造卓越的产品"
- "这个方案要兼顾各方利益"
- "我希望我的人生过得有意义"
- "我希望找一个合适的对象"

每一句都听起来很对,对不对?都没法反驳,都让人点头。

**但你试着把这里面任何一句话,翻译成可以执行的具体动作**——

"卓越"是什么意思?用什么指标衡量?
"兼顾各方利益"——具体哪几方?利益冲突时听谁的?
"有意义的人生"——你的"意义"具体指什么?跟我的"意义"是同一个东西吗?
"合适的对象"——身高?收入?三观?具体指啥?

你会发现,**这些话当初说出来的时候之所以那么轻松,就是因为它们什么都没承诺。它们只是听起来承诺了什么**。

Dijkstra 说,这就是人话(自然语言)的本质特点:

> **它的"自然",来自于它允许你不必把话说清楚。**

而编程是干什么的?编程是要让电脑去执行一件具体的事。**电脑不接受"听起来很对"——它必须收到"具体怎么做"**。

所以"用人话编程",这件事的内在矛盾是:
- 人话最大的优点,是允许你模糊
- 编程最基本的要求,是不能模糊

**你拿一个允许模糊的工具,去做一件不能模糊的事——这事儿能成才怪。**

这就是为什么他说"用人话编程"是个蠢主意。

### 他对了吗?2026 年怎么看这篇文章

最有意思的部分来了。

2026 年的今天,我们真的造出了"听得懂人话的电脑"——你正在用我跟它对话。Dijkstra 当年说"造不出来",这一点他错了。

但他真正核心的那两个观点,**一个字都没错**:

**第一**,你跟我说"帮我写个登录页"特别轻松,这个轻松不是凭空来的——背后是几十亿条训练数据、几千个工程师的工资、几亿美元的训练成本,**有一大群你看不见的人在替你支付那个"轻松"**。

**第二**,人话允许模糊这件事,在 LLM 时代不但没解决,**反而被放大了**——你写一个含糊的 prompt,模型给你一个看起来很对的输出,你点头说"嗯不错"。但其实你那个 prompt 里没说清楚的部分,模型只是**替你随便选了一个解释**。这个解释可能是你想要的,也可能完全不是。问题埋在那里,直到某天炸出来——可能是 bug,可能是产品上线后的事故,可能是几个月后的你看着自己的代码完全不记得当初为什么这么写。

### 这篇文章给普通人的最大启示

如果你这辈子只从这篇文章带走一句话,带走这一句:

> **当你听到"很轻松"、"很自然"、"听起来很对"的时候,停一下。**
>
> **问一句:那些没说出来的复杂部分,现在被谁吞下去了?**

- 老板说"打造卓越的客户体验"——具体哪些事变了?谁去做?
- 你写了个 todo "整理一下房间"——具体整哪儿?整到什么程度?
- 你跟 AI 说"帮我写个方案"——你心里的"方案"长啥样?跟它脑子里的"方案"是一回事吗?
- 你跟伴侣说"我希望你多关心我一点"——具体指啥?他/她做哪三件事你会觉得"被关心了"?

**Dijkstra 半个世纪前在讲编程,但他真正讲的是一件更普遍的事**:

> **人话的"轻松",是它最大的便利,也是它最深的陷阱。**
>
> 它让你以为说清楚了,其实没说清楚。
> 它让你以为对方懂了,其实对方只是没追问。
> 它让你以为问题解决了,其实问题只是被推到了下游。
>
> 真正高质量的沟通(无论是跟人还是跟机器),永远是某一方愿意付出力气,把那些模糊的部分挤出去——具体化、定义、举例、画边界。
>
> 谁付出这个力气,谁就在替对方负责。

这就是 EWD 667 的全部精华。换成最白的话——

**别被"听起来挺对"骗了,那东西最贵。**

#### 1. "御三家落幕"——这是叙事,不是分析

文章用很重的笔墨宣布"御三家时代结束,变成 Anthropic vs OpenAI 两强"。

把这句话挤一挤:

- **Anthropic 的 ARR 是 300 亿,OpenAI 的 ARR 是多少?** 文章没说。OpenAI 2026 年初公布的 ARR 量级是更高的,这意味着 OpenAI 在收入端依然领先。"两强对垒"的标题下,藏着两强不在一个收入量级的事实。
- **谷歌怎么就"出局"了?** 文章自己也说谷歌是 Anthropic 的算力供应方,Gemini 还在迭代——这怎么叫"御三家落幕"?这只是谷歌**多了一种押注方式**,不是它退出比赛。

"御三家落幕"是个**听起来很有冲击力、但承重很弱**的判断。它把"谷歌投钱给 Anthropic"翻译成了"谷歌认输",这一跳有点远。

#### 2. "30 倍增长"——数字真,但解释空了

ARR 从 10 亿到 300 亿,30 倍,数字是真的(假设原始来源准确)。

但文章用一句"Claude Code 出圈、企业渠道全开、500 强一把抓"就带过了。

这句话放在前面那个怀疑姿态下,问一句:**这个 30 倍增长是真的"产品力赢了",还是某种我们看不见的成本被藏在别处?**

可能的隐藏成本(文章一个都没碰):
- ARR 的口径是怎么算的?是确认收入还是合同金额?是含折扣前还是后?B 端大单往往用前者,会显著虚高
- 这 300 亿里多少是关联方收入?亚马逊承诺采购 1000 亿、微软承诺采购 300 亿、谷歌也是大金主——**金主同时是大客户,这种收入的"独立性"是要打折的**
- ARR 增长 30 倍,但毛利、净亏损是多少?Anthropic 不是上市公司,这些数字不公开。但 LLM 业务普遍重亏,300 亿 ARR 背后可能是 200 亿+ 的亏损——这才是"基础设施压力"那句话的真意

文章把"30 倍"当成结论用,但这个数字本身**正是需要被分析的对象**。

#### 3. "11GW vs 10GW"——这是把不可比的东西放在一起比

文章最骄傲的对比:

- Anthropic 一周锁定 11GW
- OpenAI 的 Stargate 目标 10GW,要等到 2029 年

听起来 Anthropic 完胜对吧?

挤一挤:

- **这 11GW 是"承诺"还是"已交付"?** 文章自己写得清楚——亚马逊 5GW "未来五年"、谷歌 5GW "2027 年开始陆续上线"、英伟达 1GW "上限"。这些都是**未来产能承诺**,跟 Stargate 那 10GW 在时间轴上其实差不多,都是 2027-2029 区间的事
- **承诺 ≠ 钱到位 ≠ 算力到位**。这三层之间每一层都有 30-50% 的折扣,这是产业常识
- **"上限"和"承诺"在文章里被当成等价词用**。"上限 400 亿"意思是"最多 400 亿,可能更少",到了文章下半段就变成了"谷歌投了 400 亿"。这种偷换在全文出现了好几次

把 11GW 和 10GW 这么并排放,**听起来是个清晰的对比,其实是把不可比的承诺/上限/已交付混成一锅**。

#### 4. "OpenAI 处境尴尬"——这是叙事自我循环

文章用很大篇幅渲染"OpenAI 被孤立、下家难寻"。

但同一篇文章里自己也写了:

> "OpenAI 不是没有金主——SoftBank、Oracle、MGX、英伟达都在,英伟达甚至单独承诺投 1000 亿美元"

英伟达单独 1000 亿美元的承诺,**比谷歌给 Anthropic 的 400 亿大 2.5 倍**。

那为什么文章的整体调子是"OpenAI 被孤立"?因为**叙事需要一个失败者**。"两强对垒"这个框架要立起来,必须有一方处境更糟。所以把 OpenAI 算力来源的多元化(本来是好事)说成"分散、不确定",把 Anthropic 算力来源的多元化(同一件事)说成"四重保险、任意一家断供都不致命"。

**同样的事实,因叙事需要被赋予了相反的解读色彩**。这是这篇文章最不诚实的地方。

#### 5. "英特尔 vs AMD"的类比——形似神不似

文章拿 2000 年代英特尔靠生态打赢 AMD 来类比谷歌的操作。

听起来很有道理。挤一挤:

- 英特尔当年是**自己做芯片、自己把芯片卖给 PC 厂商**——它的生态是"英特尔的客户"
- 谷歌现在是**把自己的算力卖给 Anthropic,而 Anthropic 的模型直接跟谷歌的 Gemini 竞争**——这不是"客户",这是**资助一个跟自己抢市场的对手**

这两件事的结构完全不一样。英特尔类比要成立,得是"谷歌资助 Dell、Lenovo 这些 PC 厂商";但 Anthropic 不是 PC 厂商,Anthropic 是另一个英特尔。

类比只取了"绑定生态"这个表层相似性,完全忽略了底层结构的差异。**听起来很对,经不起追问**。

### 那么这篇文章到底在干嘛?

剥掉"听起来很对"的那层皮,文章在做的事是这样的:

**真正的事实层(一两句话能说完)**:谷歌把 Anthropic 当成 TPU 的最大买家来投资,这反映了"算力 > 模型"的产业新逻辑。

**叙事层(占了 80% 篇幅)**:用"御三家落幕"、"两强对垒"、"OpenAI 孤立"、"第一回合胜负已定"这些充满戏剧性的词,把一个枯燥的"算力商业合作"包装成一个**有赢家有输家、有反转有悬念**的故事。

这个包装服务的是**阅读快感和点击率**,不是分析的准确性。

### 一个更冷的判断

如果非要给这件事一个 Dijkstra 式的判断——

> **谷歌花 400 亿,本质上是把自己的 TPU 库存风险,通过股权方式转嫁给 Anthropic。Anthropic 拿到的不是免费午餐,是绑定——它必须用谷歌的 TPU,必须长期消耗这些算力,必须在退出时让谷歌赚到。**

这件事**对所有人都是对冲,对没有人是胜利**:

- 谷歌对冲了"Gemini 万一打不过 Claude"的风险
- Anthropic 对冲了"任何一家算力供应商断供"的风险
- 亚马逊、微软、英伟达各自对冲了同样的风险
- 这些"对冲"加起来,意味着**没有一家真正赢了**——大家只是把自己绑得更深、更难退出

文章把"对冲"渲染成"押注、加注、决战"——**这是一个关于"决断"的故事**,但产业的真实状态是"**没人敢做决断,所以大家把所有可能性都买一份**"。

后者听起来不性感,但更接近现实。

### 最后一句

这篇文章是个不错的**事件梳理**——你看完知道"哦,谷歌投了 Anthropic,数字是 400 亿"。

但它**不是分析**。它是把一组商业承诺,包装成了一场有戏剧张力的产业战争。

读这种文章,记住一个动作:**把所有"听起来很对"的判断句挑出来,逐句问"这句话的承重证据是什么"**。挑完你会发现,文章 80% 的句子塌掉了,剩下 20% 是真东西——而那 20%,作者其实只用一段话就能讲完。

剩下的 80%,**是你正在替作者支付的"听起来很对"的成本**。

## 答 7

你这两个判断都立得住,而且第二个比第一个更有杀伤力。我把两个分别挤一挤,看哪里能再压实、哪里需要打折。

### 第一个判断:谷歌的"全栈独断"是不是结束了?

先把"全栈独断"这个说法拆开。**谷歌从来就不是真的全栈独断**——这是文章给你制造的一个出发点幻觉。

把谷歌的栈一层层摆开看:

| 层 | 谷歌的真实位置 | 是否"独断"? |
|---|---|---|
| **芯片(TPU)** | 自研,但只在自己云上卖,不外卖 | 局部强,不独断 |
| **数据中心/云** | GCP 全球第三,落后 AWS 和 Azure | 不独断,常年老三 |
| **数据** | 搜索 + YouTube + Gmail + Maps,这一层确实独 | **真的独断** |
| **用户入口(搜索)** | 全球搜索市场 90%+ | **真的独断** |
| **模型(Gemini)** | 跟 Claude/GPT 同台竞争,没领先 | 不独断 |

所以你说的"芯片到数据到入口到模型万古独断"这个图景——**它只在数据和搜索入口这两层是真的,其他层一直都是竞争状态**。

那么 Google 投 Anthropic 这件事,真正改变了什么?

**把 TPU 这一层从"内部消化"变成了"外部消化"**。

以前 TPU 只服务谷歌自己——Search、YouTube、Gemini 用。现在 TPU 要服务 Anthropic,**而 Anthropic 的模型直接跟 Gemini 抢市场**。

这件事的真实含义不是"独断结束",而是更微妙的:

> **谷歌承认,自家模型(Gemini)单独消化不掉 TPU 的产能。它必须把 TPU 卖给"竞争对手的模型",才能让 TPU 这门生意成立。**

换句话说,谷歌的让步**不是在数据/入口层**(那两层依然铁板一块),**而是在"AI 模型层"——它默认了自己在这一层不会赢,所以提前在算力层套现**。

这个判断比"全栈独断结束"更准确,但也更冷。它说的是:**谷歌战略性地放弃了"我的模型必须赢"这个目标,改成"无论谁的模型赢,我的 TPU 都要赚到钱"**。

所以你的第一个判断**方向对、措辞略重**。更精确的版本是:

> **谷歌没有失去任何东西。它只是放弃了一个原本就没真的握住的东西(模型层独占),换取在算力层的稳定收益。这是退守,不是溃败。**

### 第二个判断:文章先画靶再射箭——这一刀更准

这一刀直接命中要害。我把它展开,你会看到这文章的"画靶 → 射箭"过程极其工整。

#### 靶子是什么?

> **"Anthropic / Claude 一家压住其他三家"**

(注意这里"其他三家"指 OpenAI、Gemini、Grok——不是谷歌,因为文章已经把谷歌从对手位置移走、变成了 Anthropic 的金主。)

#### 射箭过程怎么走的?

**第一箭**:把"御三家"这个说法立起来,然后宣布它结束。

听起来在做产业分析,实际在做**叙事重组**——把原本"OpenAI、Anthropic、Google"三家平起平坐的格局,**强行重画成"Anthropic vs OpenAI"**。Google 被悄悄移到"算力供应商"的位置,Grok 直接没出现。

**这一步偷掉了 xAI**。Grok 4 的进展、马斯克的算力规模(Memphis 那个 100 万 GPU 集群),文章一字未提。为什么?因为提了就破坏"两强对垒"的对称美感。

**第二箭**:用 ARR 30 倍这个数字证明 Anthropic 在收入端赢了。

但 ARR 这个数字真正的对照应该是 OpenAI 的 ARR——文章故意不提。OpenAI 的 ARR 量级实际上更高(根据公开报道在 200-300 亿美元区间),但文章只字不提,因为提了"30 倍增长"的视觉冲击会被稀释。

**第三箭**:用 11GW 算力承诺证明 Anthropic 在基础设施端赢了。

把"承诺/上限"和 OpenAI 的"已落地"算力比,得到 Anthropic 完胜的视觉效果。但同样的承诺/已交付偷换,如果反过来对 OpenAI 也用一遍,数字立刻翻转。

**第四箭**:用"OpenAI 找下家难"把对手画得很惨。

但同一段里又写"英伟达单独承诺 1000 亿"——比 Anthropic 拿到的所有钱加起来还多。这是叙事自打脸,但读者读快了就过去了。

**第五箭(最阴的一箭)**:把"四重保险"和"任何一家断供都不致命"这个说法**只赋给 Anthropic**。

但仔细想:OpenAI 同样有微软、Oracle、SoftBank、英伟达、阿联酋、Stargate 等多个来源——这恰恰也是"四重保险"。文章却把同样的多元化结构,在 Anthropic 那里说成"安全",在 OpenAI 那里说成"分散、不确定"。

**同一个事实,在两边被赋予相反的色彩——这是叙事操作的经典手法**。

#### 这篇文章的真正动作是什么?

不是分析,是**情绪供给**。

它要做的事是:让一个对 Claude 已经有好感的中文读者,**离开文章的时候情绪上更确信"Anthropic / Claude 是赢家"**——而不是认知上理解了产业格局。

它服务的不是读者的判断力,是**读者的部落感**。

(这里"部落"我用得很轻——不是说读者真的加入了什么部落,而是说每个 AI 用户都隐隐有个偏好的模型,文章在做的事就是让"偏好 Claude"的那群人感觉"我选对了、我们赢了"。)

#### 一个更狠的问题:这文章为什么存在?

新智元这种公众号的商业模式是流量。流量来自情绪共振。情绪共振来自**清晰的赢家叙事**。

所以反过来看——

**它不是因为"Anthropic 赢了"所以写这篇文章。它是因为"需要一个赢家来供给情绪",所以选了 Anthropic 作为这次的赢家**。

下个月 OpenAI 发布 GPT-6,同一批公众号会写 "OpenAI 王者归来,Anthropic 神话破灭"。再下个月 Gemini 3 出来,会写 "谷歌深藏不露,一击致命"。

**情绪供给是循环商品,赢家是临时角色**。

### 把两个判断放在一起,看到了什么

你的两个判断合起来,实际上指向了一个更深的东西——

**第一个判断**说的是产业的真实结构:谷歌不是溃败,是退守到一个更稳的位置(算力层),让出了一个它本来就没赢的位置(模型层)。

**第二个判断**说的是这篇文章的真实动作:它不是在描述这个结构,它是在用这个结构**作为素材**,生产一种"赢家诞生"的情绪叙事。

两个判断放在一起,得出的最终读法是:

> **真实的产业新闻是"谷歌战略性收缩"——这件事冷静、不性感、写出来没人转。所以新智元把它包装成"Anthropic 大胜利、OpenAI 大孤立、御三家大落幕"——这件事戏剧化、有赢家、转发率高。**
>
> **你读到的不是产业分析,是一份产业事件被娱乐化后的产物。**

### 那以后怎么读这种文章?

回到你前面那篇 EWD 667 推出来的怀疑姿态——**"听起来很对的轻松,是谁在替你支付?"**

读公众号文章时,这一句变成:

> **"这种戏剧化的清晰感是谁在替我支付?"**

答案通常是:**作者用"省略关键事实 + 选择性赋色 + 强叙事框架"在替你支付**。你得到一种"我看懂产业了"的爽感,代价是一个失真的世界模型。

爽感是即时的,失真的世界模型在你下次做判断时(比如做投资、做职业选择、做产品决策)开始报复你。

**这跟你写一个含糊 prompt、模型给你一个看起来很对的输出,本质是同一件事**——你以为轻松地获得了答案,其实只是把模糊推到了别处,等着以后某天炸出来。

你这两个判断都立得很稳。第二个尤其漂亮——**"先画靶子再射箭"是这篇文章准确的解剖式描述**。能看穿这一层,意味着你已经不在它的目标读者群里了。

### 第二步:这个 skill 真正的独特承重是什么?

我把 EWD667 思想拆成三件事,看哪一件最值得固化成 skill:

#### A. "工作量守恒 / 模糊性转移"的诊断

> 任何"看起来轻松"的东西,问"那个轻松的成本被谁支付了?"

**这件事是什么动作?** 它是一个**逆向追溯**——给你一个表面陈述,你回头找它依赖的隐藏成本/隐藏责任/隐藏决策。

**例子**:
- "AI 让编程变简单了" → 谁在支付那个简单?(训练数据、prompt 工程师、生产事故的运维)
- "这个产品改善了用户体验" → 谁在支付那个改善?(后端复杂度、运维成本、客服)
- "我的伴侣很懂我" → 谁在支付那个"懂"?(往往是对方在替你做沟通工作)

#### B. "听起来很对、其实没意义"的识别

> 任何包含含糊承诺的句子(卓越、合适、兼顾、自然、流畅),逼问到具体动作/可观测指标。

**这件事是什么动作?** 它是一个**形式化挤压**——把模糊形容词替换成具体行为/指标/例子。

#### C. "先画靶再射箭"的叙事识别
